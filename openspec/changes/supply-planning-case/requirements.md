# requirements — supply-planning-case

> 狀態：**in-progress** · 2026-10-19 · L2（新 repo；跨資料、KPI、預測、模擬、最佳化五個模組；新資料模型）

## Why

供應鏈示範專案多半停在「預測準不準」。計畫員每天要回答的其實是三件事：**服務水準目標怎麼定、要放多少庫存、產能怎麼排**。預測只是其中一個輸入。

本專案用一家製造商的真實日流量（SupplyGraph：孟加拉一家 FMCG 製造商，41 SKU × 221 天，訂單／生產／工廠出庫／出貨四條流量，件數與噸數兩版）走完整條決策鏈。每一步都把限制寫清楚：這份資料沒有逐單交期、沒有期初庫存，能算的東西有多少就說多少。

### 待驗證的假說（結果正反都照報）

- **H1**：服務水準目標的選擇對庫存與缺貨 KPI 的影響，大於預測模型的選擇。
- **H2**：常態近似的安全庫存公式對間歇需求 SKU 保護不足；用模擬校準後，再訂購點會不同。

## Impact

- 新增 `src/`（data、quality、kpi，之後加 forecast、simulate、optimize、classify）、`tests/`、`results/`、`scripts/`、CI。
- 原始資料不進版控（上游授權 LGPL-2.1，且可重抓）：下載腳本釘 sha256；CI 不下載資料，只跑純函式測試與已落盤結果的宣稱守門。

## US-001：資料契約（M0）

**As a** 分析者，**I want** 一個可重現、會自我檢查的資料載入層，**so that** 後面每個模型吃到的資料都相同，資料的怪處也在第一站就被看見。

#### Scenario: 下載內容被竄改或上游改版
- WHEN 下載回來的檔案 sha256 與釘住的值不同
- THEN 載入中止並報出是哪個檔案，不會靜默繼續

#### Scenario: 寬表轉長表
- WHEN 載入四條流量的件數版與噸數版
- THEN 得到一張長表 `date, sku, flow, qty_unit, qty_ton`，列數 = 221 天 × 41 SKU × 4 流量，且噸數版與件數版的日期、SKU 完全對齊

#### Scenario: 品質檢核報告
- WHEN 對長表跑品質檢核
- THEN 報告至少列出：日期連續性、負值、每個 SKU 的噸／件比是否固定、星期別訂單分布、累計出貨超前累計訂單的產品日比例、期初庫存與期初欠貨的下限、休眠 SKU 清單
- AND 每條檢核在植入對應的髒資料時必須報錯（反向測試）

## US-002：KPI 層（M1）

**As a** 非專家的主管，**I want** 幾個看得懂的服務與庫存指標，各附一句定義與一句限制，**so that** 我能判斷現在好不好、問題出在哪些 SKU。

#### Scenario: fill rate（in-full）
- WHEN 某 SKU 期間累計訂單 100、累計出貨 90
- THEN fill rate = 0.90；出貨大於訂單時不得超過 1（超出部分歸期初欠貨）

#### Scenario: FIFO 欠貨帳齡與 OTIF 代理
- WHEN 以先進先出把每日出貨分配給尚未交付的訂單批（一個 SKU 一天的訂單量＝一批）
- THEN 每批得到「在幾天內交齊」；OTIF 代理 = 在 D 天內交齊的批數比例；報表同時列 D = 0…7 的曲線，不只報一個 D
- AND 期初欠貨未知：同時跑「期初欠貨 = 0」與「期初欠貨 = 下限」兩個版本，差距寫進報告

#### Scenario: 缺貨率
- WHEN 某產品日存在超過 D 天仍未交齊的訂單批
- THEN 該產品日記為缺貨；缺貨率 = 缺貨產品日 ÷ 有效產品日（排除休眠 SKU）

#### Scenario: 庫存天數（下限）
- WHEN 以「期初庫存下限 + 累計工廠出庫 − 累計出貨」重建倉庫庫存
- THEN 庫存天數 = 庫存 ÷ 近 28 天平均日訂單；報表標示為下限

#### Scenario: ABC × XYZ 分群
- WHEN 以噸數算各 SKU 的訂單量占比，以週需求變異係數算波動
- THEN 每個 SKU 得到 A／B／C（累計 80%／95%）× X／Y／Z（CV < 0.5／< 1.0／其餘），休眠 SKU 另標 D

#### Scenario: 預測誤差指標（供 M2 使用）
- WHEN 計算 WAPE 與 bias
- THEN 低估與高估的 bias 符號相反；實際值全為 0 時 WAPE 回傳 NaN，不得回傳 0

## US-003：需求預測（M2）

**As a** 計畫員，**I want** 知道哪種預測方法在哪一群 SKU 上真的比較好、好多少，**so that** 我不會為了幾個百分點的準度去維護一個複雜模型。

#### Scenario: 不偷看未來
- WHEN 在某個起點產生特徵與訓練資料
- THEN 起點之後的任何數值改動都不會改變該起點的特徵與預測（測試直接竄改未來值驗證）

#### Scenario: 基準方法正確
- WHEN 需求是固定的週型態（每週同一天量相同）
- THEN 季節 naive 與星期平均的預測與實際完全相同；移動平均 28 不會

#### Scenario: 間歇需求方法
- WHEN 需求為常數 c
- THEN Croston 與 TSB 的平均日預測都等於 c
- WHEN 需求在某天後全為 0
- THEN TSB 的預測逐期下降，Croston 不會（這是兩者的已知差異）

#### Scenario: 比較要附雜訊帶
- WHEN 比較兩個方法
- THEN 報 15 個起點成對差的中位數、勝場數與 Wilcoxon p 值；「排除節日週」版本另報

## US-004：庫存政策模擬（M3）

**As a** 供應鏈主管，**I want** 看到「服務水準目標」與「預測方法」各自能把庫存與缺貨推動多少，**so that** 我知道該先花力氣在定目標還是換模型。

（需求一律用實際訂單重播；原寫法「需求 = 預測 + bootstrap 殘差」已改，理由見 design D8。）

#### Scenario: 完美預測不缺貨
- WHEN 需求固定、預測完全正確、安全庫存為 0
- THEN fill rate = 1，且沒有欠單

#### Scenario: 庫存守恆
- WHEN 任意一次模擬結束
- THEN 期初在手 + 累計到貨 − 累計出貨 = 期末在手；累計出貨 + 期末欠單 = 累計需求

#### Scenario: 安全庫存越多，服務不會變差
- WHEN 同一需求路徑、同一預測，只把安全庫存調高
- THEN fill rate 不下降、平均在手不下降

#### Scenario: 實際前置期越長，服務不會變好
- WHEN 政策參數按名目前置期算好後固定，只把實際前置期拉長
- THEN fill rate 不上升

#### Scenario: 安全庫存只用過去的誤差
- WHEN 計算某起點的安全庫存
- THEN 只用該起點以前的起點的誤差；竄改之後的誤差不改變結果

## US-005 至 US-007（M4–M6，開工前補完整情境）



- **US-005 產能排程 MILP（M4）**：PuLP＋CBC，週別多 SKU 有產能限制批量問題，含最小批量（噸）與換線成本；與實際生產比較庫存、欠貨、換線次數。產能不足必回 infeasible；放寬最小批量，目標值不得變差。
- **US-006 欠貨風險分類（M5）**：預測未來 7 天會不會欠貨（LightGBM vs 邏輯迴歸），時間切分，PR 曲線選門檻，輸出警示清單。隨機切分會被洩漏測試擋下。
- **US-007 溝通（M6）**：README 結論在最前面（三句話給非專家＋一張 KPI 表），每個數字都能在 `results/*.json` 找到。
